    Two-Month Work Update — data_miner repo¶

    Window: 2026-03-03 → 2026-05-03 (IST) Audience: Engineering manager (cross-functional, not CV-specialist) Author: venkatapavan.muppala@jci.com

    1. TL;DR¶

    • Shipped auto_annotation v4 — a clean-room rewrite (~25k LOC, 19 test files) replacing aav3's Redis Streams + file-checkpoint stack with a single SQLite checkpoint DB, per-model detection queueing, and CancelledError-safe async semaphores. aa = pipeline that auto-labels images using detectors + VLM verifiers.
    • Built a human review system end-to-end on Label Studio (~15.6k LOC, 414 tests passing): dedup, cross-frame static-object propagation, and four interactive smart tools (smart_visual / smart_search / smart_click / smart_track) wired to a SAM 3.1 server.
    • Added 5 new detector / VLM model servers to aav4: SAM 3.1, Rex-Omni, OmDet-Turbo, OWLv2, DART (open-vocab variant of SAM3). OVD = open-vocabulary detector — finds arbitrary classes from a text prompt.
    • Built a dataset selection pipeline that compressed 11,087 DataTang frames → 1,000 diverse picks (DINOv3 cosine dedup at τ=0.97 → 3,009 survivors → FPS to 1,000), then a 250-image balanced subset across 31 clips.
    • 71 commits, 810 files changed, +104,548 / −10,537 LOC, net +94k. All on main.

    3. Topic deep-dives¶

    auto_annotation v4 (aav4) — clean rewrite¶

    Status: shipped, supersedes aav3 (which itself was a rewrite of aav2 earlier in this window) Window activity: 14 commits, ~25k LOC in data_miner/auto_annotation_v4/ (85 Python files), 19 test files

    Why it happened (per project memo): v3 had Redis Streams bugs (stale messages, cross-job contamination, SETID stomping, infinite re-queue). File checkpoints didn't scale (~800k files at 100k images). Config and model code were tangled.

    Progress: - Phase 1: 48 files built and importing cleanly. SQLite CheckpointDB (6 tables: job_info, image_meta, proposals, stages, work_queue, failures) replaces both Redis Streams and file checkpoints. - Phase 2: Per-model detect — each detector claims a detect:{model} queue, writes to proposals, barrier-checks, then queues detect:merge. Force-rerun controls at job and model granularity. - Phase 3: Async hardening — needs_session flag so non-HTTP workers don't burn aiohttp pools; acquired flag pattern instead of async with so CancelledError during semaphore acquire doesn't trigger a bogus release; two-phase shutdown (cooperative 30s grace → forced cancel).

    Key accomplishments: - Eliminated Redis dependency from the pipeline (one fewer service to operate). - Pipeline now resumable from any stage on any subset of models without bespoke cleanup. - 3 distinct reviewer-found blockers fixed during Phase 2/3 (compound-stage work_queue mismarking, clear_downstream LIKE-pattern miss, semaphore double-release on cancel).

    Next: - Pre-existing 13 GPU-bound test failures (sam3_dart / gdino batching) and 4 unrelated test failures still on the books — none introduced by this rewrite, but they should be triaged.

    Open-vocab detector + VLM expansion¶

    Status: shipped (model servers running) Window activity: 8 commits across Apr 13–28; 5 new files in models/ + 5 in model_servers/

    Progress: - DART (training-free SAM3 → real-time multi-class OVD): explored all modes, root-caused an NMS-induced class-flip between mask vs box NMS, designed and shipped a multi-image batching subclass for DART's SAM3 predictor (commit 0bc998d, 1,506 LOC). - OmDet-Turbo + OWLv2: added with batch predictors (omdet_turbo_batch.py etc.) — broadened the detector candidate pool for the cascade. - SAM 3.1: new model + LitAPI server at port 3014, max_batch_size=1, four modes (refine, text_detect, click_mask, track). The video predictor handles single images natively, so we serve all three modes from one engine. - Rex-Omni: autoregressive VLM detector wired to aav4 (DetectorName.REX_OMNI, port 3015, max_batch_size=1). Wraps rex_omni.RexOmniWrapper (HF IDEA-Research/Rex-Omni, base Qwen2.5-VL-3B). 25 dedicated tests pass.

    Key accomplishments: - aav4 detector roster expanded from {GroundingDINO, SAM3-DART} to a 7-model menu, swappable per-job via config. - All servers run under one unified serve.py LitAPI entry point.

    Next: - aav4 keeps grounding_dino + sam3_dart by default; manual_reviewer standardizes on SAM 3.1 only. Documented in manual_reviewer/docs/detectors.md. No further integration work pending.

    Manual review system (Label Studio + ML backend + smart tools)¶

    Status: shipped, live-validated on Caifu_Center_Fewer_2 clip Window activity: 2 deep sessions (~22k JSONL lines combined), 18 commits, ~15.6k LOC in manual_reviewer/, 15 test files, 414 tests passing

    Progress (8 phases + smart-tool extensions): - Phase 1–4 (foundations): aav4 contracts (Stage.HUMAN_REVIEW, HumanReviewResult), pipeline_io readers/writers, image_meta dedup-column migration, LS docker-compose + labeling XML, image-mode cross-frame reconciler. - Phase 5/7 (merged): SAM 3.1 server (above) — same backend feeds both aav4 and manual_reviewer. - Phase 6: Rex-Omni detector exposed for aav4. - Phase 8: Detector-policy doc separating aav4 ↔ manual_reviewer detector choice. - Smart-tool extensions (collapsed to 4 user-facing tools after consolidation, commit 7e203d4): - smart_visual (within-image visual prompting, hotkey v): SAM 3.1 add_geometric_prompt end-to-end with class-aware NMS dedup. - smart_search / smart_click / smart_track: text → boxes, point → mask, exemplar → cross-frame propagation via SAM 3.1 video tracker. - track_similar + propagate_now (Apr 30, two-phase): reviewer draws one exemplar, gets all in-image similars as drafts; on accept, fires multi-seed /track to all sibling tasks in one call. Live result: 6 propagations from 2 seeds × 6 siblings on Caifu_Center_Fewer_2.

    Key accomplishments: - Tests grew 281 → 414 over the window across smart_track (+26), track_similar/propagate_now (+11), and earlier additions. - Single-source-of-truth dedup module (ml_backend/dedup.py) — IoU/NMS/dedup_against funcs reused by 4 routes; class-aware so person-on-forklift is preserved. - ML backend kept as a pure protocol adapter (no torch/sam3/transformers import) — all inference flows through SAM 3.1 HTTP. Easier to operate; Dockerfile is light. - LS XML rendered from classes.txt via build_labeling_config.py (no hand-edits) — keeps labels in lockstep with the dataset definition.

    Next: - DINOv3 propagate_static lib still exists at reconcile/propagate_static.py but is not wired to a UI button (smart_track now covers the static-object case). Safe to keep dormant. - Optional: tracker-based reconcile in headless run_reconcile.py (~200 LoC + ~100 LoC tests). Lower priority.

    Dataset curation pipeline¶

    Status: shipped; produced two reproducible artifacts Window activity: 1 session (1c4cc0b1), 1 commit (d0a59a1, 952 LOC, Apr 30), 5 scripts under scripts/dataset_selection/

    Progress: - select_diverse_subset.py: DINOv3 (facebook/dinov3-vit7b16-pretrain-lvd1689m, dim=4096) embedding + FAISS cosine dedup at τ=0.97, k_neighbors=1000, then farthest-point-sampling. - viewer_subset.py: lightweight inspection viewer for a manifest. - build_balanced_subset.py, build_yolo_subset.py: downstream subset builders that flow into YOLO training.

    Key accomplishments: - DataTang curation run: 11,087 frames → 3,009 dedup survivors (drops=8,078, 72.9%) → 1,000 selected by FPS (output/dataset_selection/datatang_diverse_1000/). - Balanced subset: 250 frames drawn proportionally across 31 source clips (output/dataset_selection/datatang_balanced_250/), exported as YOLO with dataset.yaml + classes.txt. - Embeddings cached to disk (dinov3-vit7b16-pretrain-lvd1689m_hidden_cls_embeddings/) so reruns at different thresholds are fast.

    Next: - Pipeline currently single-input-dir; fanning across multiple raw sources is manual. Could parameterize.

    5. Risks / asks¶

    • Pre-existing GPU-bound test failures in aav4 (~13 sam3_dart/gdino batching tests + 4 unrelated) — not introduced by the rewrite, but they erode the safety net for future changes. Worth a half-day triage before the next big aav4 change.
    • March work has no quantified evaluation in retained context. The qwen3.5 validator and detection-metrics overhaul shipped, but I don't have AP / recall / hallucination numbers cached. If leadership wants the validator's headline accuracy for planning, I should run the eval once and pin it.
    • Solo-on-main cadence. All 71 commits land directly on main — fast for me, but no review trail. If the team grows on this codebase, we'll need a branch/PR convention; calling it out so it's a deliberate choice rather than drift.
